# 개발 기준과 현재 한계

## 사용자 요구

- Godot 엔진의 1인 주인공 싱글 플레이 게임.
- 첨부된 두 인게임 전투 영상의 연출·애니메이팅 방식이 결과 기준.
- 원작의 내려오는 슬롯 UI 대신 별도의 하단 전투 UI.
- 스킬 모션·VFX 제작 도구. 특히 애니메이팅 도구가 최우선.
- E.G.O 및 랜덤 스킬 배정 제외. 그 외 원작 전투 규칙을 구현 대상으로 검토.
- 우선 구현하고 부족한 점을 찾아 반복 수정.

## 영상에서 관찰한 연출

약 31.73초 / 43.37초의 참고 영상에서 준비 → 빠른 접근 → 포즈 전환 → 타격 → 복귀,
캐릭터를 따라가는 카메라 확대, 짧은 타격 정지, 여러 타격의 연속, 큰 곡선 궤적과 섬광,
피격 포즈와 전투 수치 표시를 확인했습니다. 영상으로 코인 확률·정확한 피해 공식까지 확정할 수는 없습니다.
3초 간격의 전체 콘택트 시트를 먼저 확인했으며 프레임 단위 타이밍 복제는 아직 하지 않았습니다.

사용자 영상은 분석 참고 자료이며 원작 이미지·음악을 프로젝트 자산으로 추출하지 않았습니다.
현재 SVG 캐릭터는 직접 만든 임시 그림입니다.

## 구현

- 실제 Node3D 바닥·기둥·카메라 + Sprite3D 캐릭터.
- 포즈를 스텝 전환하고 위치·회전·크기·줌을 키 사이에서 보간.
- linear / smooth / snap 보간 선택. 키·포즈 개수 고정 없음.
- 시간 스크럽, 0.25/0.5/1배 재생, 정지.
- 다중 타격 이벤트: 피해, 히트스톱, 섬광, 화면 흔들림, 피격 포즈.
- 간단한 선·곡선 VFX. 색·크기·각도·지속시간 편집.
- JSON 클립 저장·불러오기, 기본 스키마 검증.
- 전투 버튼으로 재생할 때 편집한 다중 타격 데이터를 유지.

## 확인된 부족한 점 / 다음 순서

1. **시각 품질:** 현재 원화와 전장은 임시. 영상과 크게 다릅니다. 우선 한 스킬의 실제 포즈 원화·궤적을 만들어 준비/접근/타격/회복 프레임을 나란히 비교해야 합니다.
2. **편집 도구:** 현재 2.4초 고정 길이. 키 드래그, 실행 취소, 트랙 분리, 프레임 번호, 동영상 오버레이, 썸네일, 파일 선택기, 외부 이미지 검증과 사용자 오류 안내가 부족합니다.
3. **모션:** 몸통의 단일 스프라이트 전환 방식. 뼈대·부위별 애니메이션과 무기 부착점, 루트 깊이 이동, 사용자 지정 피벗은 미구현.
4. **VFX:** 현재 선과 곡선의 첫 형태. 노드 기반 조합, 파티클, 텍스처 시퀀스, 마스크, 잔상, 레이어/블렌딩 트랙, 사운드가 필요합니다. 여러 이벤트의 피해는 모두 적용되지만 동시에 겹친 VFX는 마지막 이벤트만 그립니다.
5. **카메라:** 줌과 자동 X 추적만 제공. 별도의 위치/회전 트랙, 캐릭터 화면 안전 영역, 전투 UI 숨김/접기는 필요합니다.
6. **게임 규칙:** 현재 고정 피해 공격 샌드박스. 적 AI, 턴, 속도, 합, 코인, 정신력, 흐트러짐, 내성, 방어, 상태 효과는 미구현입니다. 이 프로토타입을 전투 시스템 완성으로 취급하면 안 됩니다.
7. **스킬:** 세 버튼은 같은 모션을 재사용하며 피해만 배율 적용합니다. 각 스킬에 클립을 연결하는 라이브러리와 스킬별 전투 데이터를 분리해야 합니다.
8. **설계:** 현재 `workshop.gd`에 UI·재생·샌드박스를 모았습니다. 다음 확장 전에 클립 데이터/재생기/편집 UI/전투 판정을 분리해야 합니다.

원작과 같은 결과라는 판정은 아직 할 수 없습니다. 실제 원화가 들어간 한 스킬부터 영상 대조로 검증하는 것이 다음 기준입니다.
